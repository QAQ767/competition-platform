# 团队备赛计划与流程优化

## 使用方式

进入队伍详情，默认打开「备赛计划」。队长可以新建任务；尚无任务的队伍可以生成四阶段计划：准备阶段、专项训练、模拟冲刺、作品提交。

生成时可填写备赛目标时间；留空则使用竞赛开赛时间。目标时间至少在一天后，四个阶段按可用时间分配截止日期。生成后可调整任务，不会覆盖已有任务。

任务支持标题、说明、阶段、优先级、当前队伍成员负责人、截止时间和本队训练资料。成员可开始或完成自己负责的任务，队长可管理所有任务。完成时可以填写复盘，系统保存完成时间；重新打开会清除本次完成时间和复盘。

看板展示整体完成度、未来三天待办、逾期任务和各阶段完成数，支持按阶段、负责人及逾期状态筛选。逾期提示在打开页面时计算，并每分钟刷新；它是页面内提醒，不是定时站内信。新任务分配给其他成员时发送站内通知，成员完成任务时通知队长。

## 接口扩展

沿用原任务接口，所有操作仍需登录，并由后端校验权限。

| 方法与路径 | 行为与权限 |
| --- | --- |
| `GET /api/teams/{id}/tasks` | 当前成员查看任务；返回阶段、优先级、资料名称/地址和完成复盘等字段 |
| `POST /api/teams/{id}/tasks` | 队长创建任务 |
| `PUT /api/tasks/{taskId}` | 队长编辑任务；支持清空负责人、截止时间和资料关联 |
| `PUT /api/tasks/{taskId}/status` | 当前负责人或队长更新状态；可选 `completionNote` |
| `DELETE /api/tasks/{taskId}` | 队长删除任务 |
| `POST /api/teams/{id}/tasks/plan` | 队长为无任务队伍生成四阶段计划；可选 `targetDate` |

创建及编辑请求：

```json
{
  "title": "完成一轮模拟训练",
  "content": "按竞赛时长完成模拟题，整理问题清单",
  "phase": "模拟冲刺",
  "priority": "重要",
  "assigneeId": 2,
  "deadline": "2026-10-01 18:00:00",
  "resourceId": null
}
```

阶段取值：`准备阶段 / 专项训练 / 模拟冲刺 / 作品提交`。优先级取值：`普通 / 重要 / 紧急`。状态取值：`待完成 / 进行中 / 已完成`。未提供阶段、优先级的旧创建请求分别使用准备阶段、普通。

标题最长 100 字、说明最长 500 字、复盘最长 1000 字。负责人和资料必须属于当前队伍；离队成员不能更新旧任务。日期接受 `yyyy-MM-dd HH:mm:ss` 或 `yyyy-MM-dd`，只有日期时按当天 23:59:59 处理。

## 邀请与登录流程

- 邀请通知增加 `inviteId` 和查询时计算的 `inviteStatus`。前端按通知的邀请 ID 操作，不再选择邀请列表第一条。
- 已读状态独立于邀请处理状态。标记全部已读后，待处理邀请仍可接受或拒绝。
- 处理邀请只将关联通知标记为已读。缺少关联 ID 的历史通知引导到个人中心处理。
- 队伍变更使用数据库行锁；接受或拒绝邀请时再次读取并锁定邀请记录，避免并发重复入队。
- 事务内产生的通知在提交成功后才通过 WebSocket 推送，回滚不推送。
- 并发过期请求共用一次凭证刷新；刷新失败时同时清理 Pinia 与本地登录状态。重新登录返回原页面。
- 组队搜索从第一页开始；过时的请求结果不会覆盖较新的筛选结果。

## 部署与数据库兼容

前后端需要一起更新。后端启动时执行 `PreparationSchemaUpgrade`，仅为已有的 `team_task` 和 `notification` 表补齐缺失字段；可重复执行，保留旧任务及其他历史数据。数据库账号需要有添加字段的权限。新数据库直接使用更新后的 `schema.sql`。

装饰图标统一使用 Element Plus SVG 图标，按实际使用的图标注册。统计页只引入柱状图所需的 ECharts 模块，不新增生产依赖。

## 验证

在项目根目录执行：

```sh
mvn -s competition-platform/maven-settings.xml -f competition-platform/backend/pom.xml test
npm --prefix competition-platform/frontend run build
```

后端包含 26 项测试，其中 11 项使用真实 MyBatis、事务和 H2 MySQL 模式，覆盖任务持久化、权限、完成复盘、旧库升级、事务通知、并发计划生成及并发邀请处理；其余为原有队伍流程的单元测试。H2 仅作为测试依赖，不改变正式 MySQL 配置。

浏览器验收使用独立模拟接口，不将测试数据写入应用或用户数据库。真实 MySQL、Redis 和 WebSocket 部署联调仍应在运行环境中进行。
