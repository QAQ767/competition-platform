# 管理员近期赛事发现：实现与使用说明

更新日期：2026-10-20  
入口：管理员登录后进入“后台管理 → 赛事发现”。

## 1. 流程

```
搜索关键词 / 官方公告 URL / 粘贴公告文本
        ↓
搜索适配器（可选）→ 受限网页抓取（URL 模式）
        ↓
正文提取（模型优先，规则兜底）
        ↓
来源与逐字段证据入库
        ↓
重复检测（来源 URL + 名称/主办方/年份/赛道）
        ↓
草稿 DRAFT → 管理员编辑/确认 → READY → 幂等发布 → PUBLISHED
                              ↘ REJECTED
```

搜索只负责找网页；**没有取回正文就不会创建“已抓取”草稿**。URL 抓取失败时作业记录真实失败原因，管理员仍可粘贴正文导入。粘贴文本记录为人工提供材料，系统不会声称已核验网页。

## 2. 接口

所有接口服务端强制 `ADMIN`，前端隐藏按钮不算权限。统一返回 `{code,message,data}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/competition-discovery/status` | 搜索/模型配置状态（不含密钥） |
| POST | `/api/admin/competition-discovery/jobs` | 启动 `SEARCH` / `URL` / `TEXT` 作业 |
| GET | `/api/admin/competition-discovery/jobs/{id}` | 进度、结果、部分失败/重复 |
| GET | `/api/admin/competition-drafts?status=&page=&size=` | 分页草稿列表 |
| GET | `/api/admin/competition-drafts/{id}` | 字段、来源、证据、审核轨迹、发布阻塞项 |
| PUT | `/api/admin/competition-drafts/{id}` | 编辑/标记待发布/拒绝/重开，必须带 `version` |
| POST | `/api/admin/competition-drafts/{id}/publish` | 幂等发布，返回竞赛 ID |

### 2.1 启动作业

```json
{ "mode": "SEARCH", "keyword": "数学建模", "direction": "建模", "region": "全国", "windowDays": 90, "maxResults": 10 }
```

```json
{ "mode": "URL", "url": "https://example.edu.cn/notice/123" }
```

```json
{ "mode": "TEXT", "pageTitle": "关于举办…的通知", "text": "……公告正文……" }
```

`SEARCH` 至少需要关键词或方向；`URL` 仅允许 http/https 公网目标；`TEXT` 正文 20–20000 字。

### 2.2 编辑草稿

`action`：

| action | 说明 |
|---|---|
| `SAVE` | 保存字段，状态保持 `DRAFT` |
| `MARK_READY` | 保存并通过发布前校验，状态 `READY` |
| `REJECT` | 必须填写 `reviewNote`，状态 `REJECTED` |
| `REOPEN` | `REJECTED → DRAFT` |

`version` 必须等于当前版本，否则 **409**。已发布草稿不可直接改写；如需更正，由管理员明确编辑原竞赛（`PUT /api/competitions/{id}`，仅 ADMIN）。

## 3. 字段与证据

草稿字段：

- 名称、主办方、年份、届次、赛道、级别、简介、方向标签、参赛条件；
- 报名开始、报名截止、开赛时间；不明留空；
- 原始 URL、规范化 URL、网页标题、来源单位、抓取时间、来源类型、提取模式；
- 缺失字段、冲突、提示、重复候选、过期原因、审核状态、版本、发布竞赛 ID。

每个关键字段的证据来自实际取回/粘贴的正文。模型返回但正文中找不到的片段会被丢弃；模型省略证据时，系统只在字段值确实出现在正文时用原文句子补齐，找不到就不补。

方向标签由名称/正文关键词推断时，会写入 `warnings`，提示管理员确认后才作为平台标签。

## 4. 日期规则

- 日期必须有完整年月日；只有月日时不推算年份，留空并记录冲突/缺失。
- 同一公告出现多个报名截止（校内/区域/全国/不同赛道）时不静默择一，留空并列出候选。
- 只有日期的报名截止按北京时间当日 **23:59:59** 暂存，并标记 `signupEndPrecision=DATE`；发布前必须勾选“确认按当日截止解释”。
- **证据必须支撑取值，而不只是“片段出现在正文”**：
  - 服务端会解析证据片段里的日期，要求与字段值是同一天；不一致直接置空并写入冲突（例如模型给 2027-12-31、原文是 2026-09-25）。
  - 解析证据所在分句的语义：写“开赛/比赛时间”的日期不能当报名截止，写“报名开始/开放”的日期也不能当报名截止；写“报名”的日期不能当开赛时间。
  - 区间写法（“2026年11月1日至12月20日”“即日起-2026年11月25日”）会区分开始与结束，填错位置同样置空并说明。
  - 正文只有月日、没有年份时，不认模型补出的年份。
  - 同一片段里出现多个不同的报名截止时判为归属不明，不静默择一。
  - **时刻与精度同样核对**：原文写明的时刻（`12时00分`、`12:00`、`12点`、`12点半`、`下午3点`、`上午9时` 等）必须与取值一致；原文有时刻而模型用 DATE 精度归一为 23:59:59、或改成别的时刻，都拒绝。原文只有日期时，模型也不能无依据补造精确时刻（含 00:00；仅截止字段的 DATE+当日末是约定转换）。
  - **时刻三态**：原文确实未给时刻、成功解析、有时刻线索但无法可靠解析（如中文数字“十二点”、残留“刻/秒”）。第三种不得按“只有日期”继续，必须留空/阻塞审核、提示人工核对。
- 文本字段同理：主办方、赛道、届次的证据片段必须真的包含该字段值；很短的赛道值（如“全国”）若只是长词的一部分，不算支持。等级从“全国”归一为“国家级”后，原句不再作为“国家级”的证据。
- 模型把整句简介写进赛道时清空该字段，避免污染身份判断与学生端展示。
- 管理员手工修正字段时，审核记录会保存每个字段的**修改前后值**（`changeSummary`），便于追溯审核后改了什么。
- 开赛时间早于报名截止、报名开始晚于截止等异常只提示人工核对，不强制假设。

## 5. 重复检测

两层：

1. **来源 URL**：去掉 `www.`、跟踪参数、末尾斜杠，排序 query 后比较。
2. **赛事身份**：名称归一化（去标点/空格/常见公告前后缀）+ 主办方 + 年份 + 届次 + 赛道。

判定规则：

| 判定 | 条件 | 结果 |
|---|---|---|
| 同一实例 `EXACT` | 名称+主办方相同，年份/届次/赛道**不冲突**；或同 URL 且上述字段不冲突 | 不创建草稿，作业报告 `duplicateType/duplicateId` |
| 明确不同 `DIFFERENT` | 名称+主办方相同，但年份不同、届次不同或赛道不同 | 创建草稿，写入“可能是新一届/不同赛道”的疑似提示；确认差异并填写说明后可发布 |
| 身份不完整 `INCOMPLETE` | 名称+主办方相同但缺年份/届次，且无 URL 佐证 | 创建草稿，必须人工确认是否同一届 |
| 名称不同 `NONE` | 名称相似度不足 | 同 URL 时仍写入“来源复用”提示；否则只按相似度提示 |

要点：

- **URL 只是线索，不是身份**。同一入口每年复用、同一篇通知覆盖多个赛道都很常见；只有 URL 相同而年份/届次/赛道也明确不同时，才允许创建新草稿。
- 届次会做归一：“2026年第八届”“第八届”“第8届”“八届”“8届”视为同一届（中文数字统一解析为数值，覆盖 1–99，含“第十届/第10届”）；真正“第八届/第九届”是不同实例。届次无法可靠解析的写法（非数字文本）不能仅凭文本不同就断定新实例，进入人工核验。整句赛道不参与身份比较。
- `compare` 的判定与数据库唯一键 `identity_key` 使用**同一套归一结果**；届次归一算法调整后，启动时 `PreparationSchemaUpgrade` 会重算全部历史身份键，冲突只记录告警、不删除也不静默取舍。
- 编辑名称/主办方/年份/届次/赛道后**重新查重**，旧的“差异确认”自动失效。
- 差异确认不能放行同一实例：`duplicateCandidates` 里带 `同一实例` 的条目会变成阻塞项，勾选确认也无法绕过。

## 6. 发布校验（服务端）

发布前必须满足：

- 名称、主办方、报名截止存在；
- 报名截止晚于当前时间（过期草稿不能作为“近期赛事”发布）；
- 有可追溯来源：规范化 URL，或人工粘贴正文 + 审核备注注明出处；
- 只有日期的截止已确认解释；
- 疑似重复已确认差异，并填写具体差异说明（新届次/新赛道）；
- 不存在“同一实例”的疑似重复；
- 存在日期/来源冲突时，审核备注已说明处理结果；
- 草稿状态为 `READY`，且 `reviewedVersion == version`（审核后内容未被改动）；
- 发布请求必须携带页面版本 `?version=`：未发布草稿缺失该参数直接返回 400，防止旧页面/旧链接误发布已变更的草稿。

发布在事务中：行锁 → **重新查重** → 创建竞赛 → 保存来源关联 → 回写 `publishedCompetitionId` 与唯一 `publishKey`。

- 行锁 + 唯一 `publishKey` + `competition.identity_key` 唯一索引，保证同一草稿双击/并发、不同草稿指向同一赛事实例时最多创建一条。
- 已发布草稿再次发布返回同一竞赛 ID（幂等），带过期 `version` 调用也返回原 ID。
- 前端发布时携带页面版本 `?version=`，版本不一致返回 409，避免旧页面发布已变更的草稿。

### 审核状态

- `MARK_READY` 记录 `reviewedVersion`；
- 状态为 `READY` 时修改任一内容字段，草稿自动退回 `DRAFT`，`reviewedVersion` 清空，日期解释/重复确认等过期标记一并失效；
- `REJECTED` 草稿不能直接编辑或标记待发布，必须先 `REOPEN`。

## 7. 作业状态与恢复

`QUEUED → RUNNING → SUCCEEDED | PARTIAL | FAILED`

- `SUCCEEDED`：全部命中都创建草稿；
- `PARTIAL`：部分抓取/提取失败或部分重复；
- `FAILED`：没有创建任何草稿。
- 进程重启时，遗留 `QUEUED/RUNNING` 自动标记为 `FAILED` 并提示可重试，避免永久转圈。
- 并发作业数由 `discovery.job.concurrency` 限制；超出时明确失败。
- 单个作业有整体时限（`discovery.job.timeout-seconds`，默认 300 秒）：每个命中处理前检查剩余时间，超时即停止处理后续命中，结果标记 `truncated=true` 并在 `failures` 里记 `JOB_TIMEOUT`；前端轮询到该标记会提示“作业超时截断，可重试处理剩余命中”。

## 8. 安全

- 只允许 HTTP/HTTPS；拒绝回环、私网、链路本地、云元数据、IPv6 唯一本地地址、CGNAT、保留网段。
- 端口限制 80/443/8080/8443；拒绝带用户名/密码的 URL；最大 3 次重定向，每次重新校验。
- TCP 连接固定到已校验的 IP；HTTPS 仍按原域名做证书与主机名校验，降低 DNS 重绑定风险。
- 抓取超时 15 秒、正文最大 2 MB、响应头最大 32 KB；解压后仍限制大小，避免压缩炸弹。
- 仅提取 HTML/文本；PDF 未实现时提示粘贴文本。
- 页面脚本/样式被清除；模型把正文视为不可信数据，不能调用数据库或发布工具。
- 搜索/模型密钥只从环境变量注入，不返回浏览器，不写日志。

### fake-IP 环境说明

本机代理可能把公网域名解析到 `198.18.0.0/15`。默认策略拒绝该段。仅本地联调可设置：

```bash
DISCOVERY_ALLOW_FAKE_IP=true
```

生产环境必须保持 `false`，否则会削弱 SSRF 防护。

## 9. 配置

```yaml
discovery:
  search:
    provider: ${SEARCH_PROVIDER:none}          # none / brave
    api-key: "${BRAVE_SEARCH_API_KEY:}"
    endpoint: ${SEARCH_ENDPOINT:https://api.search.brave.com/res/v1/web/search}
    country: ${SEARCH_COUNTRY:CN}
    lang: ${SEARCH_LANG:zh-hans}
  fetch:
    timeout-seconds: ${DISCOVERY_FETCH_TIMEOUT_SECONDS:15}
    max-bytes: ${DISCOVERY_FETCH_MAX_BYTES:2097152}
    max-redirects: ${DISCOVERY_FETCH_MAX_REDIRECTS:3}
    allow-fake-ip: ${DISCOVERY_ALLOW_FAKE_IP:false}
  job:
    max-results: ${DISCOVERY_MAX_RESULTS:10}
    concurrency: ${DISCOVERY_CONCURRENCY:2}
    timeout-seconds: ${DISCOVERY_JOB_TIMEOUT_SECONDS:300}   # 单作业整体时限，超时截断
```

Brave 配置：设置 `SEARCH_PROVIDER=brave` 和 `BRAVE_SEARCH_API_KEY`，重启后端。未配置时状态接口返回“未启用联网搜索”，URL/文本导入仍可用。

## 10. 错误码

| code | 场景 |
|---|---|
| 400 | 参数缺失、URL 非法、正文过短、日期格式错误 |
| 401 | 未登录 |
| 403 | 非 ADMIN |
| 404 | 作业/草稿不存在 |
| 409 | 草稿版本冲突、已发布草稿不可改写、发布冲突 |
| 503 | 搜索 API 未配置/暂不可用、作业并发已满 |

## 11. 演示步骤

1. 管理员登录，后台管理 → 赛事发现；确认顶部显示搜索/模型真实状态。
2. 选“官方公告 URL”，粘贴一个真实公告地址，启动作业。
3. 轮询完成后查看草稿：字段、逐字段证据、来源、抓取时间、缺失/冲突/重复提示。
4. 补齐/修正字段，勾选日期解释确认，填写审核备注，标记“待发布”。
5. 发布到学生端；再点一次发布，确认返回同一竞赛 ID。
6. 学生端首页/竞赛详情可见新赛事；草稿状态为 `PUBLISHED`。
