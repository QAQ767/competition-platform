# 协作档案、赛事与组队演示数据

本批次包含 7 个原始学生演示账号的空白协作档案、16 个新增虚构学生、10 场明确标注演示性质的赛事，以及 14 支队伍（13 支招募中、1 支满员）。不新增虚构获奖证明，不修改真实赛事日程。

数据源：`backend/src/main/resources/demo/scenarios-20261014.json`。个人简介与项目经历标明虚构，覆盖后端、前端、交互、统计、建模、论文、硬件、算法、测试、机器学习和路演。包含每周仅 3 小时的熟练前端、每周 16 小时的初学者，以及不参赛和仅浏览用户，用于验证推荐对能力、时间及意愿的处理。

## 导入方式

新建空数据库时随原始演示数据自动导入。已有数据库需先备份，然后在后端启动时显式传入 `--demo.scenarios.enabled=true`（或环境变量 `DEMO_SCENARIOS_ENABLED=true`）。普通启动默认不导入。

导入先补齐旧库字段，再使用事务一次性写入本批次。`demo_seed_batch` 中的 `collaboration-demo-20261014` 记录阻止重复导入。账号或赛事名称冲突时整个批次回滚，不覆盖冲突记录。只给用户名和原始昵称均匹配的 student1—student7 填充空白字段；保留已有非空内容、密码、头像、参赛意愿、技能、以及显式填写的每周 0 小时。其他用户不修改。

赛事日期按首次导入时的北京时间日期计算，报名截止覆盖之后 5—126 天，开赛覆盖之后 12—147 天；重启不会顺延日期。历史赛事和原有队伍均保留。新队伍的截止时间早于对应赛事报名截止，人数与成员记录一致。
